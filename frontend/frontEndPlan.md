# DutchSalaryToday 前端架构分析

## 技术栈架构

### 核心技术选型
- **React 19**: 最新稳定版本，函数式组件架构，支持并发特性
- **TypeScript 5.8**: 严格类型检查，编译时安全保障
- **Vite 7.0**: 现代构建工具，ESM原生支持，快速热更新
- **Tailwind CSS v4**: 最新版实用优先CSS框架，语义化类名
- **Recharts 3.1**: React专用数据可视化库，声明式图表
- **React Router v6**: 现代客户端路由，嵌套路由支持

### 开发工具链
- **ESLint + Prettier**: 代码质量和格式统一
- **Testing Library**: React组件测试
- **Vitest**: 快速单元测试框架

## 代码架构模式

### Custom Hooks 模式
- **关注点分离**: 业务逻辑从UI组件抽离到自定义hooks
- **统一状态管理**: 每个数据域都有专用hook管理
- **代码复用性**: hooks可在多个组件间共享使用

### Service Layer 架构
- **API抽象层**: 统一的数据获取和错误处理机制
- **类型安全**: TypeScript接口定义确保API契约一致性
- **容错设计**: 网络异常和响应错误的统一处理

### 类型优先开发
- **接口驱动**: API类型定义驱动开发流程
- **严格类型检查**: 编译时捕获潜在错误
- **自文档化**: 类型定义即文档，提高代码可读性

## 项目结构分析

### 模块化组织
```
src/
├── hooks/           # 自定义hooks：数据管理和业务逻辑
├── services/        # API服务层：统一数据获取
├── types/           # TypeScript类型定义
├── pages/           # 页面组件：路由级别组件
├── components/      # 可复用组件
└── assets/          # 静态资源
```

### 职责分离原则
- **hooks/**: 专注数据状态管理和业务逻辑
- **services/**: 纯粹的API调用和数据转换
- **types/**: 类型定义和接口契约
- **pages/**: UI展示和用户交互逻辑
- **components/**: 通用UI组件和交互行为

## 数据流架构

### 基于Hooks的状态管理
- **useStoryData**: 核心洞察数据管理，首页和故事页共享
- **useGapTrends**: 薪资差距趋势数据和图表交互状态
- **useGrowthRankings**: 增长排名数据和动态行业选择状态

### API集成模式
- **统一响应格式**: `{ data?, error? }` 标准化API响应
- **错误边界**: 网络异常、HTTP错误、数据异常的分层处理
- **Loading状态**: 细粒度的加载状态管理，提升用户体验

### 数据流特点
- **单向数据流**: Props down, Events up 的React经典模式
- **异步状态管理**: useEffect + useState 管理异步数据获取
- **状态派生**: 复杂UI状态基于原始数据派生计算

## 已完成核心功能

### 架构一致性修复
- **统一Custom Hooks模式**: HomePage和IceAndFirePage都采用hooks数据管理
- **消除代码重复**: 移除组件内直接API调用，统一到service layer

- **严格类型定义**: 精确使用React.Dispatch<React.SetStateAction<T>>
- **零编译错误**: 达到零TypeScript编译错误状态

### 动态UI交互
- **可点击行业选择器**: Growth Champions区域直接点击选择
- **实时视觉反馈**: 选中/未选中状态的视觉区分
- **状态同步**: 选择状态和图表数据的实时同步更新

### 数据一致性
- **API数据统一**: rankings和trendData使用一致的行业名称
- **前后端映射**: Mock API数据结构和前端类型定义对齐
- **状态管理**: 选择状态在hook内部统一管理
